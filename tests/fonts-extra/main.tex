% The font families this image installs so that they can be selected by name, as
% Overleaf documents them
% (https://www.overleaf.com/learn/latex/Questions/Which_OTF_or_TTF_fonts_are_supported_via_fontspec%3F).
%
% fontspec resolves a family name through fontconfig, and `\newfontfamily`
% resolves it **when it is declared**, not when it is first used - so this file
% fails to compile when one of these families is missing, which is exactly the
% error it exists to catch ("The font ... cannot be found"). That was measured,
% not assumed: a file that declares a family which does not exist fails, even
% though it never typesets anything in it.
%
% Nothing is typeset in most of these families on purpose. A font that has no
% Latin characters at all (Noto Serif Yezidi, the Lohit families, ...) makes
% XeTeX fail with "there are no glyphs in the subset" as soon as Latin text is
% typeset in it - a fatal error, not a warning - so a sample sentence per family
% would test something other than what this example is for. The sample below is
% rendered in the main font, to keep the route from a family name to a PDF on
% the page.
%
% The command names are made of letters only, and that is not a style choice:
% digits are not letters in TeX, so `\newfontfamily\testC059{C059}` defines
% `\testC` and hands the lone `0` to fontspec as the font name - which fails
% with `The font "0" cannot be found`, a message that says nothing about the
% real mistake. Two of the families below (`C059`, `Z003`) are why this file
% spells their command names out.
%
% Every family name was read out of the font files of the package that provides
% it, not derived from the package name: `fonts-kacst` for example has no
% `KacstOne` (that is `fonts-kacst-one`), the Thai packages provide `Tlwg Typo`
% and not `TLWG Typo`, and `fonts-khmeros` has no plain `Khmer OS`.
%
% Add a family here when the image starts installing it, and remove one when it
% stops: this file is the list of what the image promises.

\usepackage{fontspec}
