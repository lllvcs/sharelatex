\documentclass{article}

% Shell-escape, which is what an externalizing package needs: a compile that runs
% a program, and a program that writes a file into a subdirectory which the
% document then reads back. `texlive/LatexMk` and `texmf.cnf` are checked for
% this in tests/verify-overlay.sh; this example proves it end to end, and the
% latexmkrc next to it explains why it is compiled with XeLaTeX rather than with
% the LuaLaTeX of the shared rc (\write18 does nothing under LuaTeX).
%
% It deliberately does not use \tikzexternalize. pgfplots' externalization
% compiles each figure in a second run whose wrapper is
%
%     \def\tikzexternalrealjob{\jobname}\input{\jobname}
%
% and Overleaf calls latexmk with `-jobname=output` while the source keeps its
% own name, so that wrapper looks for a file called output.tex, which does not
% exist: the figure fails with "! Emergency stop" in its own log while the
% surrounding document still produces a PDF. Naming the source in
% `external/system call` is the workaround for a -jobname setup, and it is what
% an Overleaf user with such a figure has to do; it is not what this image
% demonstrates.
\begin{document}

Shell-escape writes a file into a subdirectory:

\immediate\write18{mkdir -p subdir}
\immediate\write18{printf 'generated by a system call' > subdir/content.tex}

\input{subdir/content.tex}

\end{document}
